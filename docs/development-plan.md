# 18 天开发、理解与验收计划

每天可用 8–10 小时：约 2 小时基础学习、4 小时实现/排障、2 小时独立验证、1 小时记录，剩余缓冲。不要连续生成所有模块再试图背代码。此计划用于本人逐步理解、重做和扩验证；Codex 已生成的代码不意味着这些天的个人验收完成。

阶段优先级：核心可运行→明细范围这一差异化→反例测试→模型实测/部署→文档→审核后开源。所有个人完成情况从未验收开始，不自动打勾。目标指标是验收要求，实际数值只从验证记录读取。

## 每阶段独立复现

1. **选型**：打开 selection.md 的同类链接，自己写出“已有”和“仍需验证”的两列，不能只复述 Codex 给的评分。
2. **核心**：激活环境，`python -m pytest tests/test_verifier.py -q`；改一份模拟报价，先在纸上算期望再调用 verify。
3. **HTTP/存储**：启动服务，选择正常报价→核验→人工确认→再次核验→导出；请求旧 UUID，证明原结果保留。
4. **模型**：只把来源传给 `/api/extract`，自己对照字段，记录模型版本/digest与失败；模型失败不是规则测试失败。
5. **部署**：新目录或干净克隆安装，执行 README；使用导出的 JSON 运行 `python -m linescope.replay 文件.json`。按 operations.md 备份恢复。
6. **开源/面试**：用户审核后才公开；用新终端照 README 操作，现场展示一个未预演的错误。简历只写本人完成并理解的部分。

## 14 天压缩 / 20 天缓冲

压缩到 14 天时合并 2–3、8–9、11–12、16–17；砍掉非必要 UI 美化、PDF 和批量导入，保留范围核验、金额复算、人工门禁、反例、导出重放和部署。不能为赶工取消测试/误报说明，也不能把未安装/未运行写成已交付。

第 19–20 天作为真实模型失败、Docker 网络或 Windows 安装缓冲。若到第 10 天仍无法独立解释核心，先停止扩功能，用剩余时间完成理解和反例；将版本标为核验器原型，避免编造完整 AI 项目经历。

## Codex 协作方式

每步给 Codex：当前模块、输入输出、一个正确例和一个失败例、只允许改的文件、验收命令。要求先定位根因再最小修改。提交前看 diff；提交信息说明行为，不把运行测试视作本人理解证明。个人记录使用 `docs/personal-understanding.md`，保持未填写的部分真实空白。

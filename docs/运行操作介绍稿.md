# LineScope Quotes 运行操作介绍稿

适用：在当前这台已配置好的 Mac 上，演示 Docker 版项目。建议预留5～8分钟，实际取决于语速、点击和模型生成等待时间。方括号里的内容是操作提示，不需要读出来。本文是演示稿，不表示用户已经独立掌握所有实现。

统一访问地址：<http://127.0.0.1:18765/>。

## 一、可以照读的完整稿

### 1. 介绍项目

[操作：先打开 Docker Desktop，进入 Containers 页面。]

大家好，下面我演示 LineScope Quotes，一个在 Codex 辅助下搭建的 AI 报价抽取与核验原型。

它主要处理两类问题：第一，AI 虽然提取出了数字，但可能拿到了另一条明细里的数字；第二，报价原文自己的金额合计也可能有错误。因此，这个项目不仅提取信息，还会检查来源范围和金额关系，并保留结果供人工复核。

这次使用的是自制模拟设备报价，不是真实客户材料。

### 2. 启动项目，解释 Docker 和 Ollama

[操作：找到 linescope-review。若已停止，点击这一行右侧的▶；已经运行则保留当前状态。点击左侧的>展开，确认app容器处于运行状态。不要操作其他项目。]

Docker 页面里的 linescope-review，就是这个项目。里面的 app 容器负责运行网页和 Python 后端。启动后，我在浏览器打开本机的18765端口，进入项目页面。

[操作：打开 http://127.0.0.1:18765/。]

这里还有一个软件叫 Ollama。它的作用是在 Mac 上加载和运行 AI 模型，这次使用的模型是 Qwen3。

它们的配合过程是：网页接收报价文字，Docker 中的 Python 后端把文字发送给 Mac 上的 Ollama，模型返回候选字段，最后由 Python 检查证据和金额，再把结果显示到网页上。

所以，当前配置是应用在 Docker 中运行，模型服务在 Mac 本机运行。

### 3. 运行一次真实模型抽取

[操作：点击①正常报价。先展示来源文本，再点击“使用已配置的本地 Ollama 抽取”，等待请求完成。不要连续点击。]

页面中有来源文本和候选抽取两个区域。刚载入的内置候选是手工准备的演示数据；我现在点击本地 Ollama 抽取按钮，才是在真正调用模型。

这份模拟报价有两条明细：三台笔记本电脑，单价1200元，金额3600元；两台显示器，单价450元，金额900元。两条明细的合计是4500元。

[操作：等待完成后，查看候选JSON和结果区域。]

模型会把名称、数量、单价、金额和对应的原文引用整理成候选数据。后端随后核对这些证据，并重新计算金额。

如果本次返回与样例一致，可以看到总额复算为4500元。但页面仍然显示“待人工复核”，因为金额一致不能自动证明没有漏行、没有错认字段，也不能自动确认报价是否有额外费用。

模型每次的输出也可能不同。例如，名称可能带上行号前缀，所以仍然需要对照原文检查。

### 4. 人工复核与保存新版本

[操作：逐项核对当前候选和来源。需要改的字段先修改；修改来源或候选后，先前的确认会清除。]

接下来，我对照来源核对两条明细，确认字段是否正确、是否遗漏，以及是否属于简单计价。

[操作：展开“复核确认（AI无权代填）”。只有实际核对后才勾选“明细完整且没有串行”和“无额外税费、运费、折扣的单币种报价”。填写复核者标记及实际核对依据，再点击“核验并保存新版本→”。]

完成核对后，我填写复核标记和理由，再保存一个新版本。如果所有限定检查都通过，状态会变为“限定检查通过”。

这里的通过仅表示当前支持范围内的规则通过，不是自动批准采购。新的复核记录会保留父版本，便于之后查看原始候选和修改过程。

[操作：点击一个字段的↗按钮，展示原文高亮；再展示“导出本次证据与报告JSON”的入口。]

点击字段按钮，可以看到它在来源文本中的具体位置；导出的JSON则包含来源、候选、复核说明和检查报告，供之后离线复算。

### 5. 演示原文金额错误

[操作：点击②原文少计300元，再点击“核验并保存新版本→”。这一步使用内置手工候选，先不要点击Ollama抽取按钮。]

接下来的两个场景是程序内置的受控错误样例，用来展示核验逻辑，不是让模型每次都故意出错。

现在这份原文把合计写成4200元，但两条明细相加应该是4500元。后端会显示差额为负300元，并给出总额不一致的错误，阻止通过。

这说明，即使候选数据忠实保留了原文，原文里的金额关系也仍然需要检查。

### 6. 演示引用串到其他明细

[操作：点击③引用串到另一行，再点击“核验并保存新版本→”。]

这个场景把第二条明细中的数量2，作为第一条明细的数量证据。数字2确实出现在同一页，但它不属于第一条明细。

因此，系统会指出证据超出了当前明细范围，阻止这条候选通过。项目检查的不只是“有没有这个数字”，还包括“这个数字是否来自当前明细的证据范围”。

需要说明的是，明细范围本身也是候选信息，仍然需要人工核对，不能把字符串匹配理解成完整的语义判断。

### 7. 停止和再次启动

[操作：切回 Docker Desktop，找到 linescope-review，指向这一行右侧的蓝色■停止按钮。需要现场停止时再点击。]

演示结束后，可以点击 linescope-review 右侧的蓝色方块停止应用容器。之后需要使用时，再点击播放按钮启动。

停止容器不会删除命名卷中的记录；红色垃圾桶是删除操作，不是暂停。停止这个应用容器，也不会自动关闭在 Mac 上单独运行的 Ollama。

目前这个版本支持文本形式的简单人民币报价，还不支持PDF扫描件、OCR或复杂税费计算。它主要展示的是从模型抽取、规则核验到人工复核和结果保留的完整流程。

## 三、上台前准备和故障处理

1. 先自己完整走一遍流程，确认Docker应用与本机Ollama均可用。真实模型生成需要等待，耗时随冷加载和设备情况变化，不承诺固定秒数。
2. 模型服务已经运行时不要再启动第二份；当前使用的是项目专用安装，终端未必有全局`ollama`命令。
3. 若出现MODEL_UNAVAILABLE，先检查Ollama是否运行、端口是否为11435；若MODEL_HTTP_ERROR，检查模型标签。错误信息应如实展示，不切换手工候选假装是真实推理成功。
4. 页面无法访问时先看linescope-review中的app是否运行。停止容器后，已经载入的页面内容可能还在，但按钮请求会失败。
5. 导出JSON包含来源文本，公开演示只使用自制模拟或有授权且脱敏的材料。

### 当前这台Mac的恢复命令

仅在图形界面启动不能解决问题时使用。在项目根目录执行；新电脑的安装另看README。这些命令不是需要朗读的介绍稿内容。

如果本机Ollama服务没有运行，在一个终端启动，并保留该终端：

```bash
OLLAMA_HOST=127.0.0.1:11435 \
OLLAMA_MODELS="$PWD/.local/models" \
OLLAMA_NO_CLOUD=1 \
.local/runtime/Ollama.app/Contents/Resources/ollama serve
```

在另一个终端启动当前Docker配置：

```bash
PATH="/Applications/Docker.app/Contents/Resources/bin:$PATH" \
LINESCOPE_PORT=18765 \
OLLAMA_CONTAINER_BASE_URL=http://host.docker.internal:11435 \
OLLAMA_MODEL=qwen3:1.7b \
docker compose -p linescope-review up -d --wait
```

这台机器的模型已经下载，日常启动不需要重复pull。项目的首次安装、构建及下载仍可能需要网络。容器到宿主模型的连接在当前Mac上已实测，其他电脑需独立核对。
